# Flash Mode 2 (scp push) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port legacy `init.d/87-flash_mode_2` to Rust: bring up the network, tell the operator where to push a `wic.bmap` and a `wic.xz` over `scp`, and flash the image onto the running disk.

**Architecture:** Mode 2 adds `net.rs`, `bmap.rs` and `scp.rs` to `src/mode/flash/`, a `/proc/mounts` sweep to `unmount.rs`, and three build-time constants. It unmounts everything on the running disk, brings `eth0` up with `dhcpcd`, starts `dropbear`, creates a FIFO the operator's `scp` streams into, waits for the operator, flashes with `bmaptool`, and reboots.

**Tech Stack:** Rust 2024, `nix` 0.29 (`mkfifo`, `chown`, `getifaddrs`), external `ip` (busybox), `dhcpcd`, `dropbear`, `bmaptool`, `xz`.

**Spec:** `docs/superpowers/specs/2026-08-13-flash-modes-design.md` — §2.7, §2.8, §3.3, §3.6, §5, §6, §7, §8.

**Base:** the mode 1 code on the flash branch. It is the blueprint for every task below: before a task, read the matching mode 1 module and copy its patterns — an `*Ops` trait for the side effects so a test can pin their order (`CloneOps`, `EfiOps`), `with_mount`, the `FlashError` shapes, a named `const` for every tool path and flag, `cfg` gating per item, and the test style (`logging::capture::SERIALIZE`, fake sysfs trees, fake command output). A new pattern needs a reason written here.

- `src/mode/flash/rawio.rs`, gated on `flash-mode-1`: `copy_range`, `KIB`, `COPY_BUFFER_SIZE`.
- `src/mode/flash/unmount.rs`, gated on `flash-mode-1`: `unmount_rootfs` only.

- `crate::config::BuildConstant` and `FlashError::{MissingBuildConstant, InvalidBuildConstant, CopyFailed, …}`, every variant `RecoveryClass::Fatal`.
- `BootEnvKey::FlashMode`. Mode 2 adds **no** boot-env key of its own.
- `Cargo.toml`: `default = ["core", "flash-mode-1"]`.

## Confirmed decisions

- **§10.1 — keep `non_bmap_dd_handling`.** Zero the head of the disk (boot offset plus boot size, KB) before flashing.
- **§10.5 — log unless the disk may be partly written**, as `flash-mode-2.log` on the data partition.
- **§10.8 — the `wic.bmap` wait stays unbounded**, and there is no `bmaptool` watchdog.
- **Direct flashing is a cargo feature**, `flash-mode-2-direct`. The recipe enables it when `OMNECT_FLASH_MODE_2_DIRECT_FLASHING` is `1`.
- **The omnect uid/gid is a build constant**, `OMNECT_USER_ID`. The distro configuration fixes it and `omnect_user.bbclass` uses it, so the init does not look it up in `/etc/passwd`.
- **The flag file `/etc/enforce_flash_mode` stays a runtime check.** One `omnect-os-init` package goes into every initramfs; the flag is added by a separate image recipe, so the binary cannot know it at build time.
- **Flag present, boot env unavailable or unreadable → mode 2**, as legacy, which checks the flag before it reads any env. This is open for the reviewers.

## Global Constraints

As in the mode 1 plan: no magic numbers or path literals, `crate::` imports only, comments explain why, Conventional Commits with `Signed-off-by: Jan Zachmann <50990105+JanZachmann@users.noreply.github.com>`, and the branch is append-only once pushed.

### Task 6: `scp.rs` — the mode 2 sequence

**Files:** create `src/mode/flash/scp.rs` (gated `flash-mode-2`); `src/mode/flash/rawio.rs`; `src/mode/flash/mod.rs`

```rust
const OMNECT_HOME: &str = "/home/omnect";
const WIC_FIFO_NAME: &str = "wic.xz";
const WIC_BMAP_NAME: &str = "wic.bmap";
/// The verify pass writes the mapped, decompressed image here, in RAM.
const WIC_MATERIALIZED_NAME: &str = "wic";
const BMAP_POLL_INTERVAL: Duration = Duration::from_secs(1);
```

- [ ] **Step 1: Write the failing tests**
  - `zero_head_kib(BOOT_START, BOOT_SIZE)`: the sum; either missing → `MissingBuildConstant` naming it; overflow → `InvalidBuildConstant`. The byte length uses `rawio::kb_to_bytes`, as mode 1 does.
  - `OMNECT_USER_ID` missing → `MissingBuildConstant(OmnectUserId)`.
  - `bmap_instruction(ip)` contains `scp <bmap-file> omnect@<ip>:wic.bmap`; `image_instruction(ip)` contains `scp <wic-image> omnect@<ip>:wic.xz`.
  - an order test through `ScpOps`, like `clone.rs`: constants checked before anything is touched; unmount → network → FIFO + chown → dropbear → bmap instruction → bmap wait → image instruction → verify pass → zero head → flash → EFI (grub only) → sync. With `flash-mode-2-direct`: no verify pass, and the flash reads the FIFO.
  - `rawio::zero_range` zeroes exactly the asked range of a temp file.
- [ ] **Step 2: Run them and watch them fail**
- [ ] **Step 3: Implement** `run_scp(&ScpCtx { layout, rootfs })`, in that order. The FIFO is created with `nix::unistd::mkfifo` (mode `0600`) and handed to `OMNECT_USER_ID` with `nix::unistd::chown`. The bmap wait is unbounded and logs once when it starts (spec §7); it ends when `wic.bmap` is a regular file that ends with the closing `</bmap>` tag (spec §5.4). The target disk is the layout's root block device; the EFI boot partition is the layout's boot partition. `rawio` is widened per item: the shared constants and `kb_to_bytes` on `flash-mode`, `zero_range` on `flash-mode-2`, `copy_range` stays with mode 1.
- [ ] **Step 4: Run them and watch them pass**, also with `flash-mode-2-direct`.
- [ ] **Step 5: Commit** — `feat(flash): flash a wic.xz pushed in over scp`
