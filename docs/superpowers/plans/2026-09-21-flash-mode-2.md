# Flash Mode 2 (scp push) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port legacy `init.d/87-flash_mode_2` to Rust: bring up the network, tell the operator where to push a `wic.xz` over `scp`, and flash it onto the running disk.

**Architecture:** Mode 2 adds `net.rs`, `bmap.rs` and `scp.rs` to the `src/mode/flash/` module built in the mode 1 plan, plus two build-time constants. It unmounts everything on the running disk, brings `eth0` up with `dhcpcd`, starts `dropbear`, creates a FIFO the operator's `scp` streams into, waits for the operator, flashes with `bmaptool`, and reboots.

**Tech Stack:** Rust 2024, `nix` 0.29 (`mkfifo` via `fs`, `chown` via `user`), external `dhcpcd`, `dropbear`, `bmaptool`.

**Spec:** `docs/superpowers/specs/2026-08-13-flash-modes-design.md` — §2.7, §3.0, §3.6, §5, §6, §7, §8.

**Depends on:** `docs/superpowers/plans/2026-09-21-flash-mode-1.md`, which must be merged first. It creates `src/mode/flash/{mod,config,efi,rawio,unmount}.rs`, `FlashError`, `BootMode::Flash`, the `flash-mode` feature and the early dispatch in `run_init`.

## Confirmed decisions

- **§10.1 — keep `non_bmap_dd_handling`.** Zero the first `ZERO_HEAD_SIZE` KB of the disk before flashing. The legacy comment records post-flash boot failures on both GRUB (mismatched `bootx64.efi` checksums) and U-Boot (boot-partition errors after `bmaptool`). The root cause was never established, so this may be masking a `bmaptool` or alignment problem — it is ported as-is rather than dropped on a guess.
- **§10.5 — best-effort log after a successful flash only.** Modes 2 and 3 overwrite the whole disk; after a failure it is half-written and mounting anything on it is unsafe.
- **§10.8 — the `wic.bmap` wait stays unbounded**, and there is no `bmaptool` watchdog. This wait is for a person, not a machine; a timeout would kill a flash in progress and leave the disk half-written.

### Task 1: Feature flag and build-time constants

**Files:**
- Modify: `Cargo.toml` (`[features]`), `build.rs`

**Interfaces:**
- Produces: the `flash-mode-2` feature; `config::build::ZERO_HEAD_SIZE: Option<u64>` and `config::build::DIRECT_FLASHING: bool`.

`ZERO_HEAD_SIZE` is the sum of `OMNECT_PART_OFFSET_BOOT` and `OMNECT_PART_SIZE_BOOT` in KB. The legacy recipe computes it with `bc` because bitbake does not evaluate shell arithmetic; `build.rs` sums the two values itself and needs only the two Yocto variables. It is `Option<u64>` and absent on builds that do not set it, exactly like the existing five constants; mode 2 treats it as a missing required constant.

`DIRECT_FLASHING` is a plain `bool` defaulting to `false` when the variable is absent or is not `1`, matching the legacy `oe.utils.conditional('OMNECT_FLASH_MODE_2_DIRECT_FLASHING', '1', 'true', 'false')`.

```rust
const OMNECT_USER: &str = "omnect";
const OMNECT_HOME: &str = "/home/omnect";
const WIC_FIFO_NAME: &str = "wic.xz";
const WIC_BMAP_NAME: &str = "wic.bmap";
/// Where the verify pass materializes the mapped, decompressed image.
const WIC_MATERIALIZED_NAME: &str = "wic";
const FIFO_MODE: nix::sys::stat::Mode = nix::sys::stat::Mode::S_IRUSR
    .union(nix::sys::stat::Mode::S_IWUSR);
const BMAP_POLL_INTERVAL: Duration = Duration::from_secs(1);
```

`run_scp`:

1. `unmount_target_disk(ctx.rootfs, ctx.disk)`.
2. `net::bring_up()` → the address; `net::start_dropbear()`.
3. `nix::unistd::mkfifo(OMNECT_HOME/WIC_FIFO_NAME, FIFO_MODE)`, then `nix::unistd::chown` it to the `omnect` uid/gid looked up through the `user` feature, so `scp` can stream directly into `bmaptool`.
4. Log `operator_instructions(ip)`.
5. Poll for `OMNECT_HOME/WIC_BMAP_NAME` every `BMAP_POLL_INTERVAL`, **unbounded** — this waits for a person to start the `scp`. Log a line each poll so the console shows it is still waiting.
6. Flash, branching on `config::build::DIRECT_FLASHING`:
   - `false` — verify pass first: `bmap::copy` with `bmap: Some(wic.bmap)`, `source: wic.xz` (the FIFO), `destination: wic`. That consumes the FIFO and materializes the mapped, decompressed image in the initramfs tmpfs. Then zero the first `ZERO_HEAD_SIZE` KB of the disk, then `bmap::copy` from the materialized file onto the disk. The RAM cost of the verify pass is the size of the mapped image; that cost is why the direct path exists.
   - `true` — zero the first `ZERO_HEAD_SIZE` KB, then `bmap::copy` straight from the FIFO onto the disk, no verification.
7. `efi::handle(ctx.disk, boot_partition, ctx.machine_features)`, `sync_all()`, log, `reboot`.

Zeroing writes `ZERO_HEAD_SIZE * KIB` zero bytes at offset 0 through a new `rawio::zero_range(dst, offset, len)` that reuses `COPY_BUFFER_SIZE`.

In `mod.rs`, add the `FlashMode::Mode2` dispatch arm and make the terminal action `reboot` (`RB_AUTOBOOT`) for modes 2 and 3 while mode 1 keeps `poweroff`. Log persistence for mode 2 is best-effort onto the freshly written data partition **after a successful flash only** (§10.5); on failure the disk is half-written and mounting anything on it is unsafe, so diagnosis stays on kmsg and the console.
