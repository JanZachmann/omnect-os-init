# Flash Mode 1 (shared layer + disk cloning) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port legacy `init.d/87-flash_mode_1` to Rust: clone the running disk onto another block device from the initramfs, and build the shared flash layer that modes 2 and 3 will reuse.

**Architecture:** A new `src/mode/flash/` module with a `BootMode::Flash` dispatch variant. `run_init` checks for a flash trigger right after the boot env is opened and skips `init_setup` when one is active. Mode 1 clears its triggers first, unmounts `/sysroot`, rewrites the source partition-table dump, applies it to the destination, reformats `etc`/`data`, copies the remaining partitions, writes a default bootloader env, and powers off. All decision logic (dump rewriting, config parsing) is pure and unit-tested; command execution is a thin wrapper.

**Tech Stack:** Rust 2024, `nix` 0.29 (`fs`, `mount`, `process`, `reboot`, `user` already enabled), `uuid` 1.11 (new, `v4` only), `thiserror` 2.0. External tools via `std::process::Command` with named `const` paths, as `factory_reset/reformat.rs` already does.

**Spec:** `docs/superpowers/specs/2026-08-13-flash-modes-design.md`

**Scope:** This plan covers §2, §3, §4, §6, §7 (mode 1 row), §8, §9 and §11 (mode 1 rows) of the spec, plus `flash-mode`/`flash-mode-1` in §3.6. Modes 2 and 3 are separate plans (`2026-09-21-flash-mode-2.md`, `2026-09-21-flash-mode-3.md`). §12 is meta-omnect recipe work and is out of scope for this repo.

## Reconciliation decisions

Four points where the spec meets this branch, or meets itself, and needs a ruling. Each is settled here so no task has to improvise.

1. **Unusable `flash-mode` value → Normal boot, not a `Rejected` trigger.** The wipe-modes branch introduced `FactoryResetTrigger::Rejected` so an unusable factory-reset trigger is still answered — ODS queued it and waits for a result. A flash mode has no queuing requester: the operator sets the env key by hand. Spec §8.2 ("Unknown `flash-mode` value → Log warn → Normal boot") therefore stands, and `BootMode::Flash` carries a plain `FlashConfig`, not a trigger enum. The divergence from the neighbouring factory-reset pattern is deliberate.

2. **`reformat_ext4` moves to `src/filesystem/reformat.rs` and returns `FilesystemError::FormatFailed`.** Spec §3.5 says to share it but not what happens to its error type. It cannot keep returning `FactoryResetError` — the shared module must compile without the `factory-reset` feature. `FilesystemError::FormatFailed { device, fstype, reason }` already exists (`src/error.rs:199`). The recovery classes differ, so the factory-reset call site wraps the error back into `FactoryResetError::ReformatFailed`: `FactoryResetError::ReformatFailed` is `ContinueDegraded` (`src/error.rs:92`) and `FilesystemError::FormatFailed` is `Fatal` (`src/error.rs:75`). Wrapping keeps factory-reset behaviour byte-for-byte and gives mode 1 the `Fatal` class spec §8.2 asks for.

3. **`src/mode/flash/rawio.rs` is added to the §2.5 module list.** The spec replaces every `dd` with in-process I/O (§2.8) but gives that code no home: `mod.rs` is "dispatch, terminal action, log capture and persistence", and mode 2's zeroing needs the same primitives as mode 1's partition copies. A separate `rawio.rs` on the shared `flash-mode` gate keeps both honest. The mode 2 plan adds one more module for the same reason, `unmount.rs` for the `/proc/mounts` sweep of §5.1; those two are the only additions to the spec's module layout.

4. **Step 8 validates `UBOOT_ENV1_START` whenever `BOOTLOADER_START` is set.** Spec §4.1 step 2 validates it only on U-Boot, but step 8 computes `count = UBOOT_ENV1_START - BOOTLOADER_START` whenever `BOOTLOADER_START` is set. Legacy has the same hole (`flash-mode-1:76-79` guards the check on `grub` not being in `MACHINE_FEATURES`, `flash-mode-1:174-178` does not). In practice `BOOTLOADER_SEEK` is only set for phytec i.MX8MM, which is U-Boot, so the pair cannot occur today — but the code must not read an unvalidated constant on the strength of that. Task 10 requires both constants together.

## Global Constraints

- **No magic numbers.** Every offset, size, retry count, timeout and tool path is a named `const`. Sector size, KB multiplier and the copy buffer included.
- **No magic path strings.** Use `mount_points::BOOT` (`"boot"`) and the other `mount_points` constants, never a literal.
- **Imports and consts at the top of the file**, before `fn`/`impl`. Test-scoped imports excepted. Clippy runs with `-W clippy::items_after_statements -W clippy::items_after_test_module`.
- **`crate::` import paths only.** Never `super::`, except for a sibling module inside the same parent.
- **`recovery_class()` stays an exhaustive match** — the new `InitramfsError::Flash` variant must get its own arm.
- **Prefer `unwrap_or_else` over `unwrap()`** in non-test code.
- **Comments explain why, not what.** No PR/issue/commit references, no version numbers outside a `TODO: remove me, as soon X is CR` marker, no transient specifics (device names, IPs, machine lists).
- **Dependencies:** alphabetical in `Cargo.toml`, `default-features = false`, major.minor versions.
- **Commits:** Conventional Commits, scope `flash`. Every commit message ends with `Signed-off-by: Jan Zachmann <50990105+JanZachmann@users.noreply.github.com>`. No AI co-author trailer.

```rust
///
/// Every variant is fatal: a flash either completes or leaves the operator to
/// power-cycle. Mode 1 never writes the source disk, so a failure there costs
/// nothing but the clone.
#[cfg(feature = "flash-mode")]
#[derive(Error, Debug)]
pub enum FlashError {
    #[error("Missing build-time constant: {0}")]
    MissingBuildConstant(&'static str),

    #[error("Destination device {} is unusable: {reason}", device.display())]
    InvalidDestination { device: PathBuf, reason: String },

    #[error("Destination device {} did not appear within {secs}s", device.display())]
    DestinationTimeout { device: PathBuf, secs: u64 },

    #[error("Partition table {operation} failed for {}: {reason}", device.display())]
    PartitionTable {
        device: PathBuf,
        operation: String,
        reason: String,
    },

    #[error("Malformed sfdisk dump: {0}")]
    MalformedDump(String),

    #[error("Copy from {} to {} failed: {reason}", src.display(), dst.display())]
    CopyFailed {
        src: PathBuf,
        dst: PathBuf,
        reason: String,
    },

    #[error("Failed to assign a new UUID to {}: {reason}", device.display())]
    UuidFailed { device: PathBuf, reason: String },
```

```rust
use std::path::PathBuf;

use crate::error::FlashError;

/// Which flash mode the operator selected.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum FlashMode {
    #[cfg(feature = "flash-mode-1")]
    Mode1,
}

/// The selected mode together with the keys that mode needs.
#[derive(Debug, Clone)]
pub struct FlashConfig {
    pub mode: FlashMode,
    #[cfg(feature = "flash-mode-1")]
    pub devpath: Option<PathBuf>,
}

/// Map a `flash-mode` value onto a mode.
///
/// `None` means the value selects nothing — the caller logs it and boots
/// normally rather than failing, because an operator typo must not brick a
/// device.
pub fn parse_mode(value: &str) -> Option<FlashMode> {
    match value {
        #[cfg(feature = "flash-mode-1")]
        "1" => Some(FlashMode::Mode1),
        _ => None,
    }
}

/// Validate the `flash-mode-devpath` value.
#[cfg(feature = "flash-mode-1")]
pub fn parse_devpath(value: Option<&str>) -> Result<PathBuf, FlashError> {
    let path = value.unwrap_or_default().trim();
    if path.is_empty() {
        return Err(FlashError::InvalidDestination {
            device: PathBuf::new(),
            reason: "flash-mode-devpath is not set".into(),
        });
    }
    Ok(PathBuf::from(path))
}
```

### Task 5: `BootMode::Flash` detection and the factory-reset conflict

**Files:**
- Modify: `src/mode/mod.rs:53-89` (`BootMode`, `detect`) and its test module

**Interfaces:**
- Consumes: `FlashConfig`, `parse_mode`, `parse_devpath` (Task 4); `BootEnvKey::FlashMode`, `BootEnvKey::FlashModeDevPath` (Task 2).
- Produces: `BootMode::Flash(FlashConfig)`; `InitramfsError::Flash(FlashError::InvalidDestination { .. })` for the conflicting-trigger refusal.

Two behaviours, both from spec §3.3 and the **Decided** §10.6:

- A flash trigger and a `factory-reset` trigger set at the same time is refused. **Both triggers are cleared before the error is raised.** This is the one fatal path that runs before any mode has started, so the clear-trigger-first invariant of §2.2 does not cover it; on a release image `handle_fatal_error` halts forever, so leaving the triggers set would mean every power cycle hits the same refusal and the device never boots again.
- An unknown `flash-mode` value is logged and the device boots normally (§8.2, and Reconciliation 1).

`detect` needs a mutable boot env to clear the triggers, so its signature changes from `Option<&dyn BootEnv>` to `Option<&mut dyn BootEnv>`; `src/lib.rs:191` switches from `ctx.boot_env.available()` to `ctx.boot_env.available_mut()`.

Change `detect` to take `Option<&mut dyn BootEnv>` and read the flash trigger before the factory-reset one:

```rust
/// Detect the boot mode from the boot environment.
///
/// A set `flash-mode` selects `Flash`; a set `factory-reset` selects
/// `FactoryReset`. Both at once is refused — they act on different disks and
/// single-mode dispatch cannot perform both, so dropping one silently would
/// be the worse failure. Both triggers are cleared before that refusal is
/// raised, because a release image halts on a fatal error and would
/// otherwise repeat the refusal on every power cycle.
///
/// A `flash-mode` value that selects nothing is logged and the device boots
/// normally: an operator typo must not stop a device from booting.
/// Falls back to `Normal` when the env cannot be read. Never blocks boot.
pub fn detect(_bl: Option<&mut dyn BootEnv>) -> Result<Self> { ... }
```

The body, in order:

1. Read `BootEnvKey::FlashMode`. On `Err`, log a warning and fall through to the existing factory-reset handling.
2. On `Ok(Some(v))`, `parse_mode(&v)`. `None` → `log::warn!` and fall through.

```rust
//! In-process replacements for the `dd` calls in the legacy flash scripts.
//!
//! Every one of them is a read and a write at a byte offset, so a seek plus a
//! buffered copy covers all of them. Callers follow with `sync_all`, which the
//! legacy scripts got for free when `dd` returned.

use std::fs::{File, OpenOptions};
use std::io::{ErrorKind, Read, Seek, SeekFrom, Write};
use std::path::Path;

use crate::error::FlashError;

/// Bytes per KiB. Build-time offsets and sizes are KB-valued; block devices
/// are addressed in bytes.
pub(crate) const KIB: u64 = 1024;

/// Copy buffer. Large enough to keep a block device streaming, small enough
/// for an initramfs that shares RAM with the image it is flashing.
pub(crate) const COPY_BUFFER_SIZE: usize = 1024 * 1024;

/// Copy `len` bytes (or the rest of the source when `len` is `None`) from
/// `src_offset` in `src` to `dst_offset` in `dst`.
///
/// A source that ends early is an error: a partition copy that silently wrote
/// less than asked would produce a clone that boots and then fails.
pub(crate) fn copy_range(
    src: &Path,
    src_offset: u64,
    dst: &Path,
    dst_offset: u64,
    len: Option<u64>,
) -> Result<u64, FlashError> { ... }

/// Flush every filesystem buffer to disk.
pub(crate) fn sync_all() -> Result<(), FlashError> {
    nix::unistd::sync();
    Ok(())
}
```

`copy_range` opens `src` read-only and `dst` with `OpenOptions::new().write(true)` (never `.create(true)` — the destination is an existing block device or file), seeks both, then loops over `COPY_BUFFER_SIZE` chunks, capping the final chunk at the remaining length. An `Ok(0)` read with bytes still requested returns `FlashError::CopyFailed`. Map every `io::Error` into `FlashError::CopyFailed` with `src`, `dst` and the error text; retry on `ErrorKind::Interrupted`.

- [ ] **Step 3: Implement**

`rewrite_dump` walks the dump line by line and emits a rewritten copy:

- Reject the dump unless it declares `unit: sectors` — every size below is a sector count, and a dump in another unit would be silently mis-scaled.
- Identify the data partition by index: the line whose partition number equals `PARTITION_NUM_DATA` (Task 9 makes that constant reachable). Do **not** match on `name="data"` — the DOS dump has no names.
- `let data_sectors = data_size_kb * KB_PER_SECTOR_NUMERATOR;` with `const KB_PER_SECTOR_NUMERATOR: u64 = 2;` (a 1 KB block is two 512-byte sectors), and `const SECTOR_SIZE: u64 = 512;` where bytes are needed.
- GPT: rewrite the `last-lba:` header to `data_start + data_sectors - 1`, and the data line's `size=` to `data_sectors`.
- DOS: rewrite the data line's `size=` to `data_sectors`, and the `PARTITION_NUM_EXTENDED` line's `size=` to `data_start - extended_start + data_sectors`. Both start sectors come from the dump being rewritten, which is what fixes legacy bug 2 (spec §9): the legacy script reads the extended container's start through a relative path that its `sfdisk -d` lookup can never match, so the container ends up the wrong size on every DOS machine.
- Every other line is copied through unchanged, so `label-id`, types and names survive.
- Any missing or unparsable field is `FlashError::MalformedDump` with the offending line quoted.

`dump` runs `Command::new(SFDISK_CMD).arg(SFDISK_DUMP_FLAG).arg(device)` with `const SFDISK_DUMP_FLAG: &str = "-d";`, mapping a non-zero exit to `FlashError::PartitionTable { operation: "dump".into(), .. }`.

`apply` spawns `sfdisk <device>` with `Stdio::piped()` stdin, writes the dump, closes stdin, waits, and maps a non-zero exit to `FlashError::PartitionTable { operation: "apply".into(), .. }`.

`entry_args(target_disk)` builds the `efibootmgr` argument vector as a pure function so the test above can check it without running the tool.

`handle` does, in order (spec §6):

1. Return `Ok(())` immediately when `!has_efi(machine_features)`.
2. Parse `efibootmgr` output for `Boot####` entries and delete each with `-b <num> -B`.
3. Mount `boot_partition` at the EFI mount point.
4. Run `efibootmgr` with `entry_args(target_disk)`.
5. Write `efibootmgr -v` output to `EFI_ENTRY_DUMP_FILE` on the mounted boot partition.
6. Unmount, including on the error paths after step 3, so a failure does not leave the partition mounted.

Every non-zero exit becomes `FlashError::EfiFailed` with the tool's stderr.

`required_constants()` returns a `Constants { data_size: u64, uboot_env1_start: Option<u64>, uboot_env2_start: Option<u64>, uboot_env_size: Option<u64>, bootloader_start: Option<u64> }`, erroring with `FlashError::MissingBuildConstant` for:

- `UBOOT_ENV1_START` and `UBOOT_ENV_SIZE` under `#[cfg(feature = "uboot")]`.

`UBOOT_ENV2_START` stays optional: its absence is how a machine says it reserves no second bank (**Decided** §10.7), so mode 1 writes the second copy only when it is set.

`bootloader_area_len(bootloader_start, uboot_env1_start)` returns `Ok(None)` when `bootloader_start` is `None`, `Err(FlashError::MissingBuildConstant("UBOOT_ENV1_START"))` when `bootloader_start` is set but `uboot_env1_start` is not (Reconciliation 4), and otherwise `Ok(Some(uboot_env1_start - bootloader_start))` in KB.

`validate_destination(destination, source)` resolves both with `fs::canonicalize` and returns `FlashError::InvalidDestination` when they are equal, when the destination is empty, or when it is not a block device (`FileTypeExt::is_block_device`). Resolving both sides is what catches a symlink or alias spelling of the running disk (spec §4.1 step 4).

`run_clone` then follows spec §4.1 in order:

3. `wait_for_block_device(destination, DEST_DEVICE_WAIT)` — poll every `DEST_DEVICE_POLL_INTERVAL`, log progress, and treat a device present on the final poll as success (spec §9 bug 1). Timeout → `FlashError::DestinationTimeout`.
4. `validate_destination`.
5. `sync_all()`, then unmount `rootfs.join(mount_points::BOOT)` and then `rootfs` itself. Both are mounted by `mount_core_partitions` on both bootloaders; the boot unmount makes the raw copy in step 10 consistent, and the rootfs unmount keeps `e2image` in step 12 off a mounted filesystem.
6. `sfdisk::dump(source)` → `sfdisk::rewrite_dump(&dump, constants.data_size)` → `sfdisk::apply(destination, &rewritten)`.
7. For each role the layout defines, assert `destination_partition(..)` exists and is a block device; otherwise `FlashError::InvalidDestination`.
8. When `bootloader_area_len` yields `Some(len_kb)`: `copy_range(source, bootloader_start * KIB, destination, bootloader_start * KIB, Some(len_kb * KIB))`.
9. `reformat_ext4` on destination `ETC` with `ETC_PARTITION_LABEL` and destination `DATA` with `DATA_PARTITION_LABEL`. This is what enforces the first-boot condition on the clone.
10. `copy_range` the whole of source `BOOT`, `FACTORY` and `CERT` onto their destination counterparts (`len: None`).
11. `tune2fs -U <uuid>` with `uuid::Uuid::new_v4()` on destination `BOOT` and `ROOT_A`.
12. `e2image -ra -p <layout.root_current()> <destination ROOT_A>`.
13. Bootloader env, per feature:
    - `grub`: mount destination `BOOT`, copy `GRUBENV_SOURCE` to `GRUBENV_TARGET` under the mount point, unmount.
    - `uboot`: `copy_range(UBOOT_ENV_SOURCE, 0, destination, uboot_env1_start * KIB, Some(uboot_env_size))`, and the same at `uboot_env2_start * KIB` when that offset is set.
14. `efi::handle(destination, &destination_partition(destination, PARTITION_NUM_BOOT), machine_features)`.
15. `sync_all()`.

Steps 9 and 10 keep the legacy order: reformat before copying the other partitions.
